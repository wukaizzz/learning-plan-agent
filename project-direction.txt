项目概述
这是一个面向学生/自学者的 AI 学习规划 Agent Web App。项目核心目标是：根据用户的学习目标、考试日期、可投入时间、薄弱科目和执行反馈，生成可执行、可调整、可追踪的学习计划，并通过 generative UI 的方式把结果渲染为任务卡片、时间轴、进度面板、风险提示和可编辑表单，而不是只返回文本建议。

项目强调以下能力：

个性化学习路径生成，根据目标、时间、学科优先级和薄弱点进行规划。

动态重规划，当用户没完成任务、时间变化或优先级变化时，自动调整后续计划。

可执行任务拆解，把学习计划落成 daily tasks，而不是停留在宏观建议。

学习分析与可视化，通过 dashboard 展示完成率、学习投入、风险预警和短期重点任务。

产品定位
这个项目不是传统待办工具，也不是普通 AI Chat。它更像一个“学习项目工作台”：用户围绕某个学习目标创建一个学习空间，在空间内和 Agent 持续对话，生成或修改学习计划，查看任务、进度和计划版本。

项目重点在于体现 Agent 如何驱动界面，而不是仅体现模型问答能力；也就是说，AI 的输出应该主要转化成结构化 UI block 和应用状态，而不是长文本回复。

核心功能
多学习空间
用户可以创建多个学习空间，每个空间对应一个独立目标，例如“高数期末冲刺”“英语六级”“前端面试准备”。这样做是为了隔离上下文，避免多个目标混在同一条对话和同一版计划里。

每个学习空间有自己的聊天记录、计划版本、任务列表和进度数据。

计划版本管理
学习计划不是一次性生成后固定不变，而是会随着考试时间变化、任务未完成、用户反馈等情况不断重生成，所以需要保留 plan_versions。

用户可以查看当前计划、历史计划以及新旧计划之间的变化，例如从“常规节奏”调整为“考前冲刺版”。

Agent 对话
每个学习空间下都有独立聊天线程，用户可以通过自然语言告诉 Agent 需求，例如“我周三晚上没空”“英语太简单了，增加高数比重”。聊天记录会作为上下文的一部分，但不会每次都全量原样传给模型，而是采用“近期消息 + 摘要 + 结构化状态”的方式组织上下文。

Agent 的主要职责是：澄清需求、生成计划、根据反馈局部调整、解释推荐原因。

任务系统
每一版计划会被拆成具体任务，例如某天学习什么、学多久、是否是复习任务、优先级如何、是否已完成。任务是产品里最可执行的层，也是后续做 dashboard 和动态重规划的基础。

任务需要支持完成、延期、取消、重新分配到其他日期等状态变化。

学习分析
项目会提供一个学习 dashboard，展示完成率、连续学习天数、每科投入时长、风险项和未来几天重点任务。实时 dashboard 和学习差距识别是个性化学习产品里很重要的一部分，也能体现前端工程能力。

交互设计
应用整体采用 聊天区 + 工作区 的布局：

左侧为学习空间列表。

中间为当前学习空间的 Agent 聊天区。

右侧为 generative UI 工作区，显示计划卡片、时间轴、任务列表、进度面板、风险提示等。

Agent 返回的不是自由文本页面，而是结构化 block，例如：

summary-card

study-timeline

daily-task-list

progress-panel

risk-alert

action-bar
前端通过 schema-driven 的方式把这些 block 映射为 React 组件进行渲染，这样可以保证可控性、类型安全和可维护性。

技术方向
前端技术栈为 React + TypeScript，项目核心不是单纯调用模型接口，而是实现一个 schema-driven generative UI 系统。

推荐的前端技术方向包括：

使用 TypeScript + Zod 定义 UI block schema 和 Agent 输出结构。

建立 component registry，让 type 映射到对应 React 组件。

使用状态管理保存当前学习空间、任务、计划版本和聊天上下文。

将聊天消息和结构化学习状态分开管理，避免全部依赖原始 messages。

数据模型
项目预计包含以下核心数据实体：

study_spaces：学习空间，表示一个学习目标容器。

plan_versions：计划版本，表示某个学习空间在不同时间点生成的计划。

chat_messages：聊天消息，保存用户和 Agent 的对话历史。

tasks：计划拆解出的具体学习任务。

可选扩展：study_sessions、progress_logs、space_summaries，用于记录学习日志、统计和上下文摘要。

这些表的目标是支撑：多空间管理、计划版本切换、任务追踪、Agent 上下文恢复和数据可视化。

Agent 行为原则
这个项目里的 Agent 不是“万能助手”，而是一个面向学习规划的垂直 Agent。它的行为边界包括：

主要处理学习目标采集、计划生成、重规划和任务解释。

优先输出结构化 UI 结果，而不是冗长文本。

每轮推理基于当前学习空间的上下文，不跨空间串用状态。

长对话采用摘要压缩和状态提取，而不是无限传递完整消息历史。

项目亮点
这个项目想体现的亮点不是“AI 能生成学习计划”，而是：

Agent 驱动的生成式 UI，而不是普通问答。

计划可动态调整，而不是静态时间表。

多学习空间 + 计划版本管理，具备真实产品结构。

任务、进度、风险可视化，具备实际使用价值。

前端工程上有 schema、状态管理、组件注册表和上下文管理设计。
